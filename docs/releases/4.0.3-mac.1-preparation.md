# Omarchy MX Mac 4.0.3 preparation

The runtime integrates upstream `omacom/omarchy` tag `v4.0.3`, commit
`0534987009061cbe2dacdde4ad564092ab698d12`, on the Mac fork based at
`5c4d584d`. Product version: `4.0.3-mac.1`.

## Integration decisions

- Keep Apple Silicon package availability gates, iwd networking, Asahi/Aurora
  boot ownership, and the existing installer and hardware support boundaries.
- Import the release's authentication/plugin isolation, lock command lookup,
  sudo-expiry, sleep-hook ownership, Kitty socket restriction, and mise wrapper
  input handling. Retain the fork's valid `MISE_MINIMUM_RELEASE_AGE=0s` spelling.
- Review all nine new migrations explicitly in the Asahi migration policy.
  Existing boot-stack exclusions and unknown-migration rejection remain intact.
- Preserve ARM availability checks for optional installs. OpenClaw and Perplexity
  have upstream aarch64 recipes; include them in the companion package candidate.
  Hermes Desktop and T3 Code upstream recipes are x86_64-only and are not added
  to the ARM package set. Their menu entries require repository availability.
  Hermes CLI integration remains available independently of the desktop package.
- Install the new packaged plocate service drop-in through omarchy-settings-dev;
  removing the retired locate setup script alone would omit its replacement.

## Companion inputs

The package changes use the OpenClaw and Perplexity recipes from
`omacom/omarchy-pkgs` commit `be95483` (resolve its full identity in the handoff).
The candidate contains 41 source packages producing 57 repository packages,
plus the existing six-package runtime bundle.

Refresh ALARM into a new dated snapshot rather than editing the September 6
snapshot. Both payloads use the same frozen ALARM inputs. The Asahi platform
snapshot advances Linux to `7.1.13.asahi1-1` and U-Boot to `2026.07.asahi2-1`;
all selected package bytes and signatures must verify against the existing
pinned Asahi key. The Aurora kernel stays pinned to its existing release.

## Qualification and publication boundary

This is preparation, not a published release. Local validation logs, downloaded
inputs and package artifacts live in the sibling `evidence` directory of the
isolated workspace; the final handoff records their exact identities and status.
Graphical/boot evidence requires the M1 Pro. Test an existing 4.0.2 upgrade first,
then fresh Asahi and Aurora installations, preserving the macOS installation.

The existing ARM payload builder requires published signed candidate inputs.
Do not invent candidate digests, repoint public update channels, or claim a
payload has been built before its candidate dependencies exist. Source landing,
signed candidate publication, and the immutable ALARM snapshot publication are
separate authorization gates before local payload qualification.
